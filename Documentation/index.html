Area 3 Technical Architecture & High-Availability Topology

The enterprise topology conforms strictly to the Bank of Tanzania (BOT) Cybersecurity Guidelines and the Tanzania Personal Data Protection Act (PDPA).

Tier 1: Perimeter DMZ & Security Layer

PBZ Web Application Firewall (WAF) & DDoS Protection • Mandatory TLS 1.3 Termination with Strict HSTS • Nginx/HAProxy Reverse Proxy Load Balancer with Automated Health Checks & Instant Failover.

Tier 2: Application Cluster (Isolated Private Subnet)

Active-Active Moodle/Laravel Core App Nodes (PHP 8.3-FPM) • PBZ Corporate Banking Theme Engine • Automated BOT Regulatory Reporting Plugin • Redis In-Memory Distributed Session & MUC Caching Cluster (Sub-millisecond query latency).

Tier 3: Core Data Storage & Directory Integration

MySQL 8.0 / PostgreSQL 16 High-Availability Cluster (Primary + Synchronous Standby with Automated Backups) • PBZ Corporate Active Directory / Azure AD SAML 2.0 Single Sign-On • AES-256 Encrypted Shared Storage for Scorm & Certificates.

Security Protocols & Data Sovereignty

100% Perpetual Ownership

PBZ receives complete ownership of source code, configurations, plugins, and database schemas. Unlike proprietary SaaS, the core engine has ZERO recurring per-user license fees in perpetuity.

Sovereign Data Residency

All database records, employee profiles, assessment scores, and audit logs reside 100% within Tanzania/Zanzibar borders, fulfilling BOT regulatory mandates and PDPA compliance.

Enterprise Cryptography

Mandatory TLS 1.3 in transit with HSTS; database tablespaces and file stores encrypted using AES-256 with PBZ-managed cryptographic keys and automated key rotation.

Identity Governance & MFA

Active Directory synchronization: when employees depart the bank, their LMS access is revoked instantaneously. Mandatory Multi-Factor Authentication (MFA) for Admins and Branch Managers.

Area 5 Core Component Rationale

PBZ Management requested clarification on prototyping, content development, and ongoing maintenance. Here is the operational rationale:

1. Interactive Prototyping Phase

Eliminates End-User Adoption Risk

Delivering a clickable, interactive PBZ prototype by Week 5 allows HR, Branch Managers, and IT to test navigation, course mechanics, and reporting layouts early. This de-risks the bank and prevents expensive late-stage redesigns.

2. Interactive Content Development

Solves Compliance Retention Deficit

Static 50-page PDFs have under 15% retention, exposing PBZ to compliance failures. We convert policies into interactive SCORM/H5P branching scenarios where staff make realistic branch decisions, yielding >80% retention and verifiable audit proof.

3. Support & Maintenance SLA

Guarantees Business Continuity

Commercial banking demands strict recovery targets: Priority 1 (outage) response < 1 hr, resolution < 4 hrs; Priority 2 < 4 hrs. Includes quarterly security patches, OS updates, and local Tanzanian engineering support.
